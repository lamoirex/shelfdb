# shelfdb

Файловая база данных книг с хеш-индексами на диске и графическим интерфейсом на Qt.

Все операции выполняются напрямую над файлами базы: записи не загружаются в память
(кроме таблицы на экране, которая только отображает данные). Добавление, поиск,
удаление и редактирование по ключу работают за O(1) в среднем.

## Сборка и запуск

Нужны CMake 3.20+, компилятор с поддержкой C++17 и Qt 6 (на macOS: `brew install qt`).

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure   # тесты ядра
./build/shelfdb                              # программа
./build/shelfdb ~/books.dat                  # сразу открыть базу
```

Если Qt не найден, ядро и тесты всё равно соберутся, а CMake выведет предупреждение.

## Запись

| Поле | Тип | Роль |
|---|---|---|
| `id` | `int32_t` | первичный ключ |
| `title` | `char[64]` | название (UTF-8) |
| `author` | `char[48]` | автор (UTF-8), вторичный индекс |
| `year` | `int32_t` | год издания |
| `price` | `double` | цена |
| `available` | `bool` | есть ли в наличии |

## Файлы базы

| Файл | Содержимое |
|---|---|
| `books.dat` | заголовок (28 байт) и слоты по 154 байта: книга, ссылки на соседей по цепочке автора, ссылка на следующий свободный слот |
| `books.pidx` | хеш-таблица `id` → номер слота |
| `books.sidx` | хеш-таблица автор → первый слот в цепочке книг автора |

Слот `i` лежит по смещению `28 + i × 154`. Индексы — хеш-таблицы с открытой адресацией
(FNV-1a, линейное пробирование, надгробия при удалении, удвоение при заполнении > 70 %).
Книги одного автора связаны двусвязным списком прямо в файле данных. Удалённые слоты
попадают в список свободных и переиспользуются.

## Сложность операций

| Операция | Сложность |
|---|---|
| Добавление с проверкой уникальности `id` | O(1) амортизированно |
| Поиск, удаление, редактирование по `id` | O(1) в среднем |
| Поиск и удаление всех книг автора | O(1 + k), k — число найденных |
| Поиск и удаление по названию, году, цене, наличию | O(n) |

## Замеры

Среднее время одной операции, мкс (MacBook, Release, `build/benchmark`):

| N | Добавление | Поиск по id | Поиск по автору | Поиск по году | Удаление по id | Удаление по автору | Удаление по году |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 000 | 40.95 | 4.01 | 10.80 | 816.1 | 13.44 | 57.04 | 849.1 |
| 10 000 | 30.76 | 4.12 | 11.91 | 8 196.9 | 15.06 | 83.16 | 8 684.0 |
| 100 000 | 38.36 | 3.75 | 13.87 | 83 352.6 | 15.62 | 89.94 | 88 442.0 |
| 1 000 000 | 37.33 | 4.40 | 16.76 | 846 677.9 | 16.72 | 97.82 | 897 700.1 |

Операции через индексы не зависят от размера базы, операции без индекса растут линейно.

Запуск замеров:

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release --target benchmark
cd build-release && ./benchmark
```
